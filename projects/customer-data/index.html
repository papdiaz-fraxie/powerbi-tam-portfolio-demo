Business problem

Manual enrichment treated each client file as a new research job.

Clients supplied contact or account files for enrichment. Before repository-assisted matching, researchers worked through those files row by row and researched records from scratch.

Manual enrichment typically ran at roughly 50 records per researcher per day, making repeated research expensive when the same entity already existed in maintained data.

My response

Use maintained reference data without weakening QA.

I designed and implemented a Python-based reconciliation workflow around BigQuery. It checks the incoming client file against the latest available reference data before deeper research begins.

Matched records can be verified quickly; stale, uncertain and unmatched records still go through deeper manual research.

Operating model

A closed-loop customer-data workflow

The process improves both the current delivery and the reference repository used by future jobs.

1. Standardise intakeMap the client file into the controlled contact or account enrichment template.
2. ReconcileUse Python to compare rows with maintained BigQuery reference data.
3. Verify / researchResearchers review every row and investigate stale or uncertain records.
4. QA + deliverReturn a cleaned file with row-level outcomes plus a separate QA summary.
5. ReuseLoad the validated enrichment batch back into BigQuery through Python.
Contact matching

Strong identifiers first

  • LinkedIn URL is the main contact identifier where available.
  • Email, name/company and supporting fields act as fallback evidence.
  • Recency is checked rather than treating any historical match as current.
  • Matched records are always double-checked by a researcher.
Account matching

Entity resolution uses multiple signals

  • Company LinkedIn URL
  • Website / domain
  • Company name
  • Country / location to disambiguate similarly named entities

Where client values conflict with more current verified reference data, stale values can be replaced with the newer verified information.

Data quality

Make exceptions visible instead of silently dropping them

The enrichment templates include source, research date, status, batch and QA fields alongside the actual contact/account attributes.

Examples of contact QA outcomes

  • Duplicate
  • Valid contact but wrong title
  • Valid contact and correct title
  • Invalid contact but correct title
  • No contact information

Examples of account QA outcomes

  • Unable to find the account
  • Duplicate
  • Account Rebranded
  • Account Enriched
  • Invalid Company (Merged, Acquired, Sold)
Client deliverable: final cleaned/enriched file with row-level outcomes plus a separate QA summary/report.
