BigQuery Data Platform & Automation

Turning recurring B2B data work into a reusable environment with consistent ingestion, validation, quality controls and downstream use.

BigQuerySQLPythonpandasGoogle Apps ScriptAPIsWebhooksData Quality
Business problem

Data needed to be reusable, not repeatedly rebuilt.

B2B contact and company data was being used across campaigns, CRM workflows, reporting and client requests. To make it easier to search, reuse and manage, I set up a BigQuery-based data environment and built repeatable workflows around it.

Why it mattered

More control over recurring data work.

The value was not simply storing records in a database. The goal was consistent inputs, repeatable transformations, better validation and easier downstream use across multiple operational needs.

Workflow

From source data to downstream use

The important layer is the control between ingestion and use: standardise first, validate next, then make trusted data available to CRM, campaigns and reporting.

1. Source inputsGoogle Sheets and recurring data files
2. IngestionMove structured data into BigQuery
3. StandardisationClean and normalise with SQL / Python
4. Quality controlsValidate, deduplicate and flag exceptions
5. Downstream useCRM, campaigns, reporting and client requests
What I did

Built the operating layer around the data.

  • Set up a BigQuery-based database for B2B contact and company data.
  • Built workflows to move data from Google Sheets into BigQuery.
  • Used SQL and Python to clean, standardise and validate incoming data.
  • Used Google Apps Script, APIs and webhooks to reduce repetitive manual handling.
  • Structured data so it could be searched, reused and reported on later.
  • Added quality checks so issues could be identified before data reached downstream campaigns and CRM processes.
Controls

Examples of the quality layer

  • Missing-name and missing-email checks.
  • Email-format validation.
  • Duplicate detection and canonical-record selection.
  • Standardised fields before loading downstream.
  • Exception handling so bad records can be reviewed rather than silently passed through.
Public code shown here uses synthetic records and simplified patterns. It is not a copy of production code or client data.
Technical evidence

Example quality checks

These safe examples demonstrate the approach used to validate records and select a canonical record when duplicates exist.

BigQuery-style quality check

SELECT
  COUNT(*) AS total_records,
  COUNTIF(first_name IS NULL OR TRIM(first_name) = '') AS missing_first_name,
  COUNTIF(email IS NULL OR TRIM(email) = '') AS missing_email,
  COUNTIF(
    email IS NOT NULL
    AND NOT REGEXP_CONTAINS(
      LOWER(TRIM(email)),
      r'^[^@\s]+@[^@\s]+\.[^@\s]+$'
    )
  ) AS invalid_email_format
FROM `portfolio.raw_contacts`;

Canonical-record deduplication

WITH ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (
      PARTITION BY LOWER(TRIM(email))
      ORDER BY updated_at DESC
    ) AS record_rank
  FROM `portfolio.raw_contacts`
)
SELECT * EXCEPT(record_rank)
FROM ranked
WHERE record_rank = 1;

What this project demonstrates
